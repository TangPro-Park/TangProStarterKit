# 대전제·아키텍처 임의 변경 금지

프로젝트 *대전제* 에 해당하는 다음 자산은 사용자 명시 결정 없이 변경 금지:

- **핵심 layer 골격** (예: 프로젝트의 5-layer 또는 N-tier 정의)
- **LAYER_MAP / 카테고리 데이터 모델**
- **PROJECT_DIRECTIVE 의 핵심 다이어그램**
- **CLAUDE.md 의 계층 지도**
- **어떤 자산이든 "프로젝트 정체성" 의 일부**

**Why**: AI 는 패턴 매칭으로 *기존 구조에 새것 끼워넣기* 시도. 사용자가 의도하지 않은 architecture drift. 시각화·기능·미래호환성 욕구로 *데이터 모델 변경* 하면 — 다른 시스템 곳곳에서 호환 깨짐.

**How to apply**:
- 신규 SPEC·기능이 기존 골격에 안 맞을 때: **사용자에게 "어디에 넣을지" 물어보기**. 새 계층 자체 신설 X
- 시각화·UI 가 "데이터 부족" 으로 느껴져도 *데이터 모델 바꾸지 X — 시각화 자체를 보강* (빈 행 표시·placeholder 등)
- *cross-cut* / *횡단* 개념은 SPEC 문서·architecture 화면 시각 구분으로만 표현. 데이터 모델에 동격 항목으로 추가 X
- 모든 architecture 영향 변경은 SPEC 신설 + 사용자 명시 컨펌 후만 진행
- 이미 잘못 박았으면 *즉시 git checkout 으로 되돌리고 사과 후 보고*. 일일이 Edit 으로 손대지 말 것
