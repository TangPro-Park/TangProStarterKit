# 백그라운드 큐 실행 승인 룰

장기 배치·큐·자동화 작업의 5계명:

1. **단일 큐 원칙** — 동시에 두 개 이상의 큐 절대 가동 X
2. **명시 승인 원칙** — 큐 시작은 사용자 명시 승인 후
3. **명시 범위 한정** — 사용자가 지시한 범위 외 작업 임의 추가 금지
4. **자동 재시작 금지** — fail 시 재시작 정책은 사용자 결정. AI 가 임의 재가동 X
5. **idempotent 우선** — 모든 단계는 산출물 존재 시 자동 스킵 (재가동 비용 0)

**Why**: 큐 작업은 fail·실패 누적의 영향이 큼. 동일 자원 (네트워크·디스크·외부 API rate limit) 두 큐 경쟁 시 시스템 hang. 자동 재시작은 *비가역적 외부 호출* (결제·발송·매매) 이 결합되면 치명.

**How to apply**:
- 큐 시작 전 *반드시* 사용자에게 — *대상 인벤토리 + 예상 시간 + 비용* 보고. 명시 OK 대기.
- 진행 중 *다른 큐 추가* 시 — 기존 큐 영향 점검. 동시 가동 X.
- 사용자가 "큐 두개 더" 같이 요청 → *진행 중 큐 그대로 + 미시작만 분리*. TaskStop 으로 진행 중 큐 죽이지 말 것.
- fail 발생 — *원인 진단 보고* + 사용자 결정 대기. AI 가 자동 재시도 X.
- 모든 단계 산출물 (캐시·중간 결과) 영속화. 재가동 시 자동 skip.
