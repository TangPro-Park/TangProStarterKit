# 사용자 오더 매칭 우선

사용자 메시지가 들어오면 **다음 순서로 처리**:

1. ORDERS.md 의 트리거 표 확인 — 정확 일치 또는 명확한 의미 매칭
2. 매칭 시 — *진입점 1곳만* 읽고 즉시 액션. 광범위 Glob/Grep/컨텍스트 서치 X
3. 모호 — 사용자 확인 (추측 액션 금지)
4. 매칭 안 됨 — 정상 추론 fallback
5. 새 오더 패턴 자주 등장 시 — 사용자에게 ORDERS 등록 제안

**Why**: AI 가 매번 *대량 컨텍스트 서치* 로 의도 파악하면 토큰 비용 + 응답 지연. 사용자가 *재사용 가능한 트리거* 박제해두면 AI 는 *진입점만* 읽고 즉시 작업 가능. 시간·비용 90% 절감.

**How to apply**:
- 메시지 받자마자 *ORDERS.md 트리거 표 1초 스캔* (이미 컨텍스트에 로드됨 — CLAUDE.md §1)
- 트리거 매칭 시: 진입점에 적힌 스크립트·런북·SPEC만 *한 번* Read → 액션
- 명사가 발화에 있으면 GLOSSARY 도 *함께* 매칭 (예: "콘솔 띄워" → ORDERS ui + GLOSSARY §1)
- 같은 패턴 트리거가 *3회 이상* 등장 + 매번 같은 액션 → 사용자에게 "이거 ORDERS 에 정착시킬까요?" 제안
- 메시지가 *질문* 또는 *대화* 면 ORDERS 매칭 X — 정상 응답.
