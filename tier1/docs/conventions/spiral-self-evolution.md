# 나선형 자기진화 (Spiral Self-Evolution)

> 프로젝트가 *매 세션마다 운영 노하우를 스스로 박제*하고, 그것을 다시 헌법·런북·메모리로 환류시켜 다음 세션의 출발점을 끌어올리는 원리.
>
> 출처: PROJECT_DIRECTIVE §1.4 (project_oracle 운영에서 추출). domain 무관 generic 원리만 남김.

---

## 1. 왜 이 원리인가

AI 협업은 *세션 단위* 로 끊긴다. 세션에서 얻은 시행착오·결정·패턴이 *그 세션 안에서만* 살고 사라지면, 다음 세션은 같은 실수를 반복한다. 자기진화는 이 휘발을 막는다:

- 매 시행착오 → *룰북·메모리·컨벤션* 으로 즉시 박제
- 매 결정 → *SPEC·devlog* 로 박제
- 박제된 패턴 중 보편적인 것 → *전파 큐* 로 다른 프로젝트에 환류

→ 시간이 갈수록 출발점이 높아진다. 직선이 아니라 *나선*.

---

## 2. 나선 한 바퀴 (Cycle)

```
[작업·시행착오]
      ↓ 박제
[룰북 / 메모리 / 컨벤션 / SPEC / devlog]
      ↓ 다음 세션 자동 로드
[더 높은 출발점에서 작업]
      ↓ 보편 패턴은
[전파 큐 → starter kit / downstream]
      ↺ (다시 위로)
```

- **즉시성**: 시행착오는 *그 자리에서* 박제. "나중에"는 휘발한다.
- **환류**: 박제는 다음 세션 *자동 로드* (메모리·헌법·런북 진입점) 경로가 있어야 작동.
- **전파**: 보편 패턴은 한 프로젝트에 가두지 말고 큐로 흘려보낸다 (`docs/propagation/`).

---

## 4. 위반 시 (나선이 멈출 때)

- 시행착오를 박제 안 하면 → 다음 세션 *같은 시도-실패 반복* (가장 흔한 손실)
- 박제했는데 *자동 로드 경로가 없으면* → 죽은 문서. 진입점(메모리 인덱스·헌법 링크)에 반드시 등재
- 보편 패턴을 큐에 안 올리면 → 프로젝트 1곳에 노하우 갇힘
