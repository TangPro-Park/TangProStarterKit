# docs/red_team/ — 적대 시나리오 + 회귀 테스트 (Tier 3)

> 시스템이 *무엇에 약한가* 를 적대적 관점에서 시뮬레이션. 발견한 취약 시나리오는 회귀 테스트로 영구 박제.

---

## 언제 도입하나

- 외부 사용자 도입 후
- 안전·규제 도메인 (잘못된 응답이 사람·자산을 다치게 할 수 있는 곳)
- AI 시스템 — 프롬프트 인젝션·jailbreak 대비 필수

## 시나리오 종류

| 분류 | 예시 |
|---|---|
| **프롬프트 인젝션** | 사용자 입력에 시스템 지시 위장 |
| **권한 우회** | 일반 사용자가 관리자 행동 시도 |
| **데이터 유출** | PII / 시크릿 노출 시도 |
| **가드레일 약화** | "예외적으로 한 번만" 류 사회공학 |
| **자동 매매·거래** | 의도하지 않은 거래 트리거 |
| **업로드 공격** | 악성 파일·zip bomb·압축폭탄 |

## 작성 규칙

1. 파일명: `<공격유형>_<시나리오명>.md`
2. 한 시나리오 = 한 파일
3. *공격 절차* + *기대 시스템 행동* + *현재 시스템 행동*
4. 발견된 취약점은 SPEC 으로 승격 (Critical 은 즉시)
5. 시나리오는 회귀 테스트 자동화 — `tests/red_team/` 권장

## 표준 섹션

```
# <시나리오명>

## 1. 분류·심각도
- Type: Prompt Injection / Auth Bypass / ...
- Severity: Critical / High / Medium / Low

## 2. 공격 절차
1. (단계별 절차)

## 3. 기대 시스템 행동
(시스템이 어떻게 거부·차단해야 하는가)

## 4. 현재 시스템 행동 (실측)
- 결과: ✅ 차단 / ❌ 통과
- 증거: (스크린샷·로그·응답)

## 5. 발견된 취약점 (있을 시)
- 연관 SPEC: SPEC_NNN
- 패치 일자:

## 6. 회귀 테스트
- tests/red_team/<파일>:<함수>
```

## 운영 팁

- 분기마다 *기존 시나리오 전수 재실행* — 회귀 방지
- 새 기능 도입 시 "이 기능이 새로운 공격면을 만들었는가" 1단락 검토
- AI 시스템은 모델 업데이트마다 핵심 시나리오 재실행 권장
