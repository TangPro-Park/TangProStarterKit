# docs/methodology/ — 방법론 정의서 (Tier 3)

> 본 프로젝트가 따르는 방법론의 *프로젝트 내 사본*.
> 본 키트의 [`탱프로_개발방법론.md`](../../../탱프로_개발방법론.md) 를 복사해 *그 프로젝트에 맞게 조정*.

---

## 왜 별도 사본인가

- 방법론 본체(키트)는 모든 프로젝트의 공통 시드
- 각 프로젝트는 자기 도메인·규모에 맞게 *변형* 누적
- 변형이 일반화 가능하면 → 키트 본체에 역流 (PR)

## 운영 규칙

1. 부트스트랩 시 키트의 `탱프로_개발방법론.md` 복사
2. 첫 1개월은 *원본 그대로* — 변형 충동 자제
3. 1개월 후 본 프로젝트 특화 변형 누적 가능
4. 분기마다 키트 본체와 *중요 차이* 검토 → 일반화 가능한 건 키트로 역流

| `_PROJECT_VARIANT.md` | 본 프로젝트 특화 변형 사항만 별도 기록 |
