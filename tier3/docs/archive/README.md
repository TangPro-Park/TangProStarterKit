# docs/archive/ — 폐기·이전 버전 보존소 (Tier 3)

> 더 이상 사용 안 하지만 *흔적은 남겨야 하는* 문서 보존.
> 폐기는 삭제가 아니라 *이동*. 이 곳이 흔적의 무덤.

---

## 무엇을 옮기나

| 분류 | 예시 |
|---|---|
| 이전 버전 헌법 | `PROJECT_DIRECTIVE_v0.1.md` (현재 v0.3 일 때 v0.1·v0.2 보존) |
| 폐기된 SPEC 큰 변경 | (작은 폐기는 `Status: Abandoned` 로 specs/ 그대로) |
| 이전 ROADMAP·CHANGELOG | 분기 마감 후 분리 보관 |
| 큰 chat log·디버깅 세션 | 1회성이지만 학습 자산 |
| 이전 메서드·접근법 | "이 방법은 안 됐다" 의 증거 |

## 절대 옮기지 말 것

- ❌ 폐기된 SPEC 자체 (specs/ 에 `Abandoned` 로 남긴다 — 번호 흔적)
- ❌ devlog (시간순 일기는 절대 이동 X)
- ❌ runbook 핵심 (현재 운영 중이면 이동 X)

## 작성 규칙

1. 디렉토리 내 구조: `<원본위치>/<파일명>` 보존 (어디서 왔는지 추적 가능)
2. 이동 시 `MOVED_FROM_<원본>` 류 메모 첨부 또는 frontmatter
3. 이동 사유 1단락 — *왜 더 이상 쓰지 않는가*

## 운영 팁

- 분기 마감 시 *archive 후보* 1회 검토
- archive 가 200MB 넘으면 *역사적 가치 낮은 것* 외부 (S3·Drive) 로 이전 검토
- 다만 *기록의 권위* 유지를 위해 git 추적 권장
