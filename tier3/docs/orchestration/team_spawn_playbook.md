# 팀 spawn 플레이북 — 표준 라이프사이클

> 여러 에이전트로 미션을 수행할 때의 *처음부터 끝까지* 표준 흐름. Agent Teams(통신·관찰) 또는 Dynamic Workflows(대량·검증) 어느 모드든 공통으로 적용되는 운영 규약이다.

---

## 1. 풀 라이프사이클

```
① PM 미션 분해      미션을 멤버별 독립 작업으로 쪼갬 (파일·영역·범위 분할)
② 계획안 사전 박제   spawn *전에* 계획서를 파일로 박제 (채팅 표만으로 spawn 금지)
③ spawn             멤버 + reviewer 동시 spawn
④ tmux 관찰         총 pane 수 기준 분할로 진행 실시간 관찰
⑤ 통신             블로커·결재 요청·중간 산출물 위치 공유
⑥ 결과 박제         산출물 + 회고 + 메타를 계획서에 누적 (단일 로그)
```

> ②번 — **계획안을 spawn 전에 파일로 박제**한다. "표 보여주고 바로 spawn" 은 금지. 무엇을·누가·어디에 낼지가 휘발되면 회수가 불가능해진다.

---

## 2. ★ 산출물 규약 (TP 룰)

멀티에이전트의 가장 흔한 실패는 *결과가 어디 있는지 모름*이다. 4가지 규약으로 차단한다.

| # | 규약 | 이유 |
|---|---|---|
| TP-1 | **각 산출물의 정착 위치를 계획서에 사전 명시** | 휘발성 임시 경로(`/tmp` 등)에 두면 회수 어려움. *영구 위치를 미리* 못박는다 |
| TP-2 | **각 에이전트는 자기 업무 히스토리를 *스스로* 박제** | PM 이 대신 안 한다. 멤버가 자기 작업 로그를 표준 위치에 직접 남긴다 |
| TP-3 | **reviewer 보고서 위치 표준화** | 결재 결과를 정해진 경로에 — 예: `<계획서명>_reviewer.md` |
| TP-4 | **계획서 = 풀 라이프사이클 단일 로그** | 결과 + 회고 + 메타를 한 파일에 누적. 흩어진 산출물을 한 곳에서 추적 |

### 권장 위치 규약 (예시)

```
docs/team_plans/<날짜>_<팀명>.md            # 계획서 = 단일 로그 (TP-4)
docs/team_plans/<날짜>_<팀명>_reviewer.md   # reviewer 보고서 (TP-3)
<감사 디렉토리>/agents/<에이전트명>/<날짜>_<미션>.md   # 멤버 자기 히스토리 (TP-2)
```

> spawn 프롬프트에 "작업 종료 시 네 히스토리를 <위치>에 박제하라" 를 *자동 포함*시키면 TP-2 가 강제된다.

---

## 3. reviewer 사전 대기 패턴

reviewer 를 builder 와 *동시에* spawn 해 둔다. builder 가 작업하는 동안 reviewer 는:

- 결재 기준을 *사전에* 정의해 들고 대기
- builder 산출물을 읽기 전용으로 검토
- 완료 즉시 판정 → 통합 대기 시간 0

> builder 가 다 끝난 뒤 reviewer 를 부르면 합류·맥락 로딩 대기가 생긴다. 동시 spawn 이 핵심.

---

## 4. 운영 회고 루프 — C1·C2·C3

처음부터 완벽한 오케스트레이션은 *불가능*하다. **주기적 개선 루프**로 구조가 스스로 나아지게 한다.

| 루프 | 주기 | 다루는 것 |
|---|---|---|
| **C1** | 매주 | 이번 주 미션들의 즉각 회고 — 막힌 점·반복 델타 |
| **C2** | 2주 | 패턴 누적 검토 — 반복되는 트러블을 룰/템플릿으로 승격 |
| **C3** | 분기 | 구조 점검 — 하네스 골격·산출 규약·게이트 전면 재검토 |

> 핵심 명제 — **"의지가 아니라 구조."** "다음엔 더 잘하자" 는 의지에 기대지 않는다. *주기가 강제하는 회고*로 개선을 구조에 박는다. (METHODOLOGY 원리 — 실패 → 룰 변환, Part IX 정합.)

## 5. 시작 전 체크리스트

- [ ] 미션이 멤버별 *독립 작업*으로 쪼개졌나 (동일 대상 동시 편집 없음)
- [ ] 계획서를 파일로 박제했나 (TP-1·TP-4)
- [ ] 각 산출물의 정착 위치가 계획서에 명시됐나
- [ ] reviewer 를 동시 spawn 하도록 구성했나
- [ ] 기존에 도는 프로세스와 충돌이 없나
- [ ] spawn 프롬프트에 "자기 히스토리 박제" 지시가 들어갔나 (TP-2)
