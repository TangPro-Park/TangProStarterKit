# 🛠 하네스 엔지니어링 — 에이전트별 실행환경 구축

> **하네스(harness)** = 한 에이전트가 미션을 수행하기 위한 *실행환경의 큐레이션* — 도구·skill·프롬프트·진입점을 미션에 맞게 묶은 것.
>
> Agent Teams·Dynamic Workflows 보다 *먼저* 깔리는 설계 층이다. 환경이 부실하면 통신·병렬을 아무리 잘 짜도 결과가 안 나온다.

---

## 1. 철학 — Software 3.0 / Thin Harness, Fat Skills

- **Software 3.0** — 코드를 직접 짜기보다 *모델 + 도구 + 프롬프트*를 조합해 행동을 정의한다.
- **Thin Harness, Fat Skills** — 하네스(진입점·배선)는 *얇게*, 재사용 가능한 *능력(skill)* 은 *두껍게*. 미션마다 새 배선을 두껍게 만들지 말고, 능력을 skill 로 빼서 여러 미션이 공유한다.

> 안티패턴 — 미션마다 거대한 프롬프트를 통째로 새로 쓴다 → 재사용 0, 유지보수 폭증. 능력은 skill 로, 하네스는 *그 skill 을 어떤 도구·진입점에 꽂을지*만.

---

## 2. 하네스 구성 4요소

| 요소 | 의미 | 예 |
|---|---|---|
| **도구(tools)** | 에이전트가 쓸 수 있는 행동 표면 | 파일 읽기·쓰기·실행·웹·DB 조회 |
| **skill** | 재사용 가능한 절차·도메인 지식 묶음 | "데이터 파이프라인 적재 절차", "재무 리포트 작성 규약" |
| **프롬프트** | 역할·게이트·출력 규약 | 시스템 프롬프트 + 미션 지시 |
| **진입점** | 첫 로드 문서·맥락 | 헌법(CLAUDE.md)·해당 SPEC·관련 runbook |

미션별로 이 4요소를 *큐레이션*하는 것이 하네스 구성이다. 같은 모델이라도 도구·skill·진입점이 다르면 전혀 다른 에이전트가 된다.

---

## 3. 에이전트 라이프사이클 3종

에이전트가 *언제 살아있는가*로 환경 구성이 달라진다.

| 종류 | 수명 | 트리거 | 환경 고려 |
|---|---|---|---|
| ① **세션 종속** | 한 세션·한 작업 동안 | 사람이 spawn | 가장 단순. 끝나면 정리 |
| ② **주기(periodic)** | 반복 깨어남 | cron / loop | 멱등성·중복 실행 방지·상태 저장 필수 |
| ③ **상시 상주(resident)** | 24h 살아있음 | 외부 서버 상주 | 헬스체크·재시작·시크릿 관리·격리 필수 |

> 처음엔 ①로 시작한다. ②·③은 운영 부담(모니터링·시크릿·장애 복구)이 크므로 *수요가 검증된 뒤* 승격한다. 1~3인 팀이 처음부터 상주 에이전트를 띄우면 운영에 잡아먹힌다.

---

## 4. ★ 진화 델타 — 매 미션 종료 시 박제

하네스는 한 번에 완벽해지지 않는다. **매 미션이 끝날 때 5차원으로 무엇이 바뀌었는지** 기록하고, 그 델타를 *다음 미션 하네스 초안*에 자동 반영한다.

| 차원 | 묻는 것 |
|---|---|
| **본질(intent)** | 이 에이전트의 역할 정의가 바뀌었나 |
| **구성(composition)** | 도구·skill·진입점 조합이 바뀌었나 |
| **전달(delivery)** | 프롬프트·출력 규약·산출 위치가 바뀌었나 |
| **게이트(gate)** | 새로 추가/완화한 안전·결재 게이트가 있나 |
| **트러블(trouble)** | 이번에 막힌 것 + 해결법 (다음에 반복 금지) |

```markdown
## 진화 델타 — <미션명> (YYYY-MM-DD)

| 차원 | 이전 | 이후 | 비고 |
|---|---|---|---|
| 본질 |  |  |  |
| 구성 |  |  |  |
| 전달 |  |  |  |
| 게이트 |  |  |  |
| 트러블 |  |  |  |
```

> 반복적으로 나타나는 델타(매번 같은 도구를 추가하더라) 는 *기본 템플릿으로 승격*한다. 이것이 하네스가 스스로 진화하는 회로다.

---

## 5. 범용 하네스 템플릿 골격

```markdown
# 하네스: <에이전트명>

## 역할 (본질)
- 한 줄 정의 + 이 에이전트가 *하지 않는* 일

## 라이프사이클
- [ ] ① 세션 종속  [ ] ② 주기  [ ] ③ 상시 상주

## 구성
- 도구: (목록)
- skill: (재사용 능력 목록)
- 진입점: (첫 로드 문서 — 헌법 / SPEC / runbook)

## 프롬프트·출력 규약
- 시스템 프롬프트 위치:
- 출력 형식 / 산출 위치:

## 게이트
- 안전·결재·검증 게이트 (파괴적 명령 차단 등)

## 진화 델타 로그
(§4 표를 미션마다 append)
```

> 템플릿은 *얇게* 시작하라. 비어 있는 칸은 미션을 돌리며 델타로 채운다 — 처음부터 다 채우려 들면 stale 된다 (METHODOLOGY 안티패턴 A1 정합).
