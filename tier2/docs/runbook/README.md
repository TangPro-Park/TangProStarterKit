# docs/runbook/ — 운영 절차서

> 반복되는 운영 명령·실패 대응 절차·환경 함정. *매번 헤매는 일* 을 박제하는 곳.

---

## 작성 규칙

1. 파일명: `<주제>.md` (영어/한국어 자유, 한 단어 권장)
2. 한 파일 = 한 주제 (장애 대응 / 환경 셋업 / 외부 도구 호출 등)
3. 목차 + "🚨 검색 금지, 외워라" 류 영구 사실 섹션 우선
4. 진단 체크리스트는 *0번부터* (가장 흔한 실수)
5. 새 함정 발견 시 즉시 갱신 — 두 번째 사람은 안 헤매도록

---

## 권장 초기 파일

| 파일 | 무엇 |
|---|---|
| `docker_setup.md` | Docker 셋업·운영·장애 대응 (제공됨 — 본 키트) |
| `environment.md` | 실행 환경(WSL/venv/native) + 자주 쓰는 명령 |
| `troubleshooting.md` | 자주 발생하는 에러 + 해결 |
| `incident_response.md` | 장애 발생 시 단계별 절차 |
| `governance.md` | 큐·배치·외부 호출 운영 규칙 (5계명) |

---

## 한 파일 표준 골격

```markdown
# <주제>

> 1줄 정의 — 본 문서가 답하는 질문.

---

## 0. 🚨 영구 사실 (검색 금지, 외워라)

(반복 함정 박제 — 매번 찾지 말고 외울 사실)

---

## 1. 핵심 명령 / 절차

(자주 쓰는 명령 또는 단계별 절차)

---

## 2. 진단 체크리스트

0. (가장 흔한 실수)
1. ...
2. ...

---

## 3. 변경 이력
```

---

## 운영 팁

- 새 함정을 만나면 *그 자리에서* 추가. 메모만 하다 잊는다.
- 진단 체크리스트는 *순서가 효율* — 가장 흔한 원인부터.
- "왜 이렇게 해야 하는지" 짧은 사례 1줄 첨부 → 후속자가 룰을 약화시키는 걸 막음.
